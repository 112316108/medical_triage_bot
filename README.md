## 🔬 研究設計與評估

### 研究問題

大型語言模型（LLM）能否只靠使用者一句口語的症狀描述，做出符合臨床標準的初步分診？本專案用台灣急診五級檢傷分類（TTAS）作為參考標準，回答三個問題：

1. **RQ1 準確度與安全性**：AI 給出的三色燈號跟 TTAS 的一致程度有多高？會不會把危急病人判成不急（低估）？
2. **RQ2 提示詞設計**：專業格式、白話簡易格式、加入 TTAS 五級標準，三種提示詞的分診表現有什麼差別？
3. **RQ3 模型選擇**：不同模型（gpt-oss-120b 與 Qwen3.8-27B）表現是否不同？

### 方法

| 項目 | 內容 |
|---|---|
| 測試集 | [`evaluation/test_cases.json`](evaluation/test_cases.json)：56 題單輪口語症狀情境，TTAS 第 1–5 級依序為 8 / 15 / 12 / 10 / 11 題 |
| 標準答案 | 作者參考 TTAS 判定原則（意識、呼吸、疼痛分數與中樞/周邊部位、高風險機轉）逐題標註，並附判定理由 |
| 燈號對照 | TTAS 1–2 級 → 🔴 紅燈；3 級 → 🟡 黃燈；4–5 級 → 🟢 綠燈（對應系統「30 分鐘內就醫」的黃燈定義） |
| 提示詞設定 | `pro`：原始專業模式；`simple`：白話簡易模式；`ttas`：專業模式加上 TTAS 五級標準（[`prompts.py`](prompts.py) 的 `TTAS_ADDON`） |
| 模型 | Groq 上的 `openai/gpt-oss-120b`、`qwen/qwen3.8-27b`，temperature = 0 |
| 流程 | 2 個模型 × 3 種提示詞 × 56 題 = 336 次呼叫，由 [`evaluation/evaluate.py`](evaluation/evaluate.py) 自動解析回應中的燈號與 TTAS 級數 |

**評估指標**

- **準確率**：燈號與標準答案相同的比例。AI 沒有給出判定（例如反問使用者）也算錯。
- **低估率（under-triage）**：判得比實際不緊急的比例。這是安全性上最重要的指標。
- **高估率（over-triage）**：判得比實際緊急的比例，會造成急診資源浪費。
- **危急個案敏感度**：TTAS 1–2 級個案被判為紅燈的比例。
- **二次加權 Cohen's κ**：考慮「差幾級」的一致性指標，錯一級扣分比錯兩級少。

### 結果

**三色燈號**（完整報告：[`evaluation/results/report.md`](evaluation/results/report.md)）

| 模型 · 提示詞 | 準確率 | 低估率 | 高估率 | 危急個案敏感度 | 未判定 | 加權 κ |
|---|---|---|---|---|---|---|
| gpt-oss-120b · pro | 85.7% | 1.8% | 10.7% | 100% | 1.8% | 0.917 |
| gpt-oss-120b · simple | 75.0% | 3.6% | 16.1% | 100% | 5.4% | 0.878 |
| gpt-oss-120b · ttas | 82.1% | 1.8% | 5.4% | 100% | 10.7% | 0.953 |
| **qwen3.8-27b · pro** | **91.1%** | 1.8% | 7.1% | 100% | 0% | 0.944 |
| qwen3.8-27b · simple | 78.6% | 1.8% | 19.6% | 100% | 0% | 0.868 |
| qwen3.8-27b · ttas | 89.3% | 3.6% | 7.1% | 100% | 0% | 0.935 |

**TTAS 五級**（`ttas` 設定）

| 模型 | 完全正確 | 誤差 ≤ 1 級 | 未判定 | 加權 κ |
|---|---|---|---|---|
| gpt-oss-120b | 66.1% | 87.5% | 10.7% | 0.925 |
| qwen3.8-27b | 75.0% | 100% | 0% | 0.934 |

### 發現

1. **危急個案全部抓到**：6 種設定都把 23 題 TTAS 1–2 級個案判為紅燈（敏感度 100%）。錯誤主要是高估，這在分診上是比較安全的方向。
2. **白話提示詞會明顯降低準確度**：`simple` 模式比 `pro` 低 10–13 個百分點，而且高估率偏高（16–20%），例如把脫水、恐慌發作判成「立即急診」。推測原因是簡易提示詞拿掉了各燈號的判定標準和例子。**設計上的啟示：可以用白話回答，但判定標準不能省略。**
3. **加入 TTAS 標準沒有提升三色燈號準確率**，但讓系統能輸出五級分類。Qwen 的五級判定全部落在正確答案 ±1 級內；最常見的錯誤是把第 4 級判成第 5 級，是低風險的偏差。
4. **固定的盲點**：第 26 題「氣喘有點喘，吸藥之後有比較好，還可以講完整句子」（TTAS 3 級）在 6 種設定下**全部**被判為綠燈。模型似乎把「症狀有改善」看得比「仍有呼吸窘迫」更重。這類「好轉中但仍需評估」的情境是未來要加強的方向。
5. **gpt-oss-120b 較常反問而不下判斷**（`ttas` 設定未判定 10.7%）。這雖然符合系統提示詞「資訊不足時主動追問」的規則，但在需要快速分診的情境會降低實用性。
6. **模型選擇**：Qwen3.8-27B 在 `pro` 設定準確率最高、從不拒答，因此本系統改用這個模型（原本的 Llama-3.3-70B 已經從 Groq 下架）。

### 研究限制

- **標準答案未經臨床驗證**：測試集由作者自行參考 TTAS 原則標註，沒有經過急診醫護人員審核，部分邊界個案（例如第 3 / 4 級之間）可能有爭議。
- **樣本數小**：56 題中，1 題就等於 1.8 個百分點。設定之間相差 2–5% 可能只是隨機差異，不能視為顯著。
- **只測單輪對話**：實際使用時 AI 可以追問，資訊也會更完整。本評估只測第一句話的判斷，也沒有提供生命徵象數據（TTAS 正式檢傷會用到）。
- **每題只跑一次**：temperature = 0 雖然降低了隨機性，但沒有測重複執行的一致性。
- **模型會更新或下架**：雲端模型版本可能變動，結果只代表評估當時（2026 年 9 月）的模型。

### 重現評估

```bash
python evaluation/evaluate.py                          # 全部模型 × 全部提示詞
python evaluation/evaluate.py --limit 5                # 先試跑 5 題
python evaluation/evaluate.py --models qwen/qwen3.8-27b --conditions pro
```

已完成的題目會存在 `evaluation/results/raw_*.jsonl`，中斷後重跑會自動接續。要全部重來請先刪除 `results/`。

## 🚀 安裝與執行步驟

### 1. 環境需求

- Python **3.10** 以上
- Windows 10 / 11（PDF 中文字型需 Windows 內建微軟正黑體）

### 2. 安裝套件

開啟終端機（cmd 或 PowerShell），切換到專案資料夾後執行：

```bash
pip install -r requirements.txt
```

### 3. 設定 API Key

編輯 `.env` 檔案，將 `gsk_xxxxx` 替換成你的 Groq API Key：

```
GROQ_API_KEY=gsk_你的真實金鑰
```

> 取得 Groq API Key：前往 https://console.groq.com → 登入 → 建立 API Key

### 4. 執行程式

```bash
python triage_bot.py      # 桌面版（tkinter）
python web_app.py         # 網頁版（Gradio），瀏覽器開啟 http://127.0.0.1:7860
```

### 5. 部署網頁版（Render，選用）

網頁版可以免費部署到 [Render](https://render.com)，產生一個公開網址，別人不用安裝就能直接操作。

1. 用 GitHub 帳號登入 https://render.com
2. 點 **New → Blueprint**，選擇這個 repo（Render 會讀取 `render.yaml`）
3. 依提示在 `GROQ_API_KEY` 欄位貼上你的 Groq 金鑰，按 **Apply**
4. 建置完成後會得到 `https://medical-triage-bot-xxxx.onrender.com`

金鑰只存在 Render 的環境變數裡，不會進到 GitHub。免費方案閒置 15 分鐘後會休眠，再次開啟需要等大約 1 分鐘。網頁版有使用限制（單則 500 字、每次對話 15 輪、全站每分鐘 20 次 AI 呼叫），避免 API 額度被用光。

| 功能 | 桌面版 | 網頁版 |
|---|---|---|
| 分診對話、燈號顯示、知識庫 | ✅ | ✅ |
| 中英切換、專業/簡易模式、病患資料 | ✅ | ✅ |
| 匯出紀錄 | PDF | 文字檔（.txt） |

## 📖 使用說明

1. 程式啟動後，先閱讀並同意**免責聲明**
2. 在下方輸入框描述您的症狀
3. 按 **Enter** 傳送（**Shift + Enter** 可換行）
4. AI 會回覆包含緊急程度燈號、建議科別與行動建議
5. 對話結束後，點選 **📄 匯出 PDF** 儲存紀錄

### 🔴 緊急狀況提醒
若出現**胸痛、呼吸困難、意識不清**等症狀，請立即撥打 **119**，勿等候 AI 回應。

## 🛠 常見問題

**Q：執行後出現「API Key 錯誤」？**
A：請確認 `.env` 中的 `GROQ_API_KEY` 已填入正確金鑰，且不包含多餘空格。

**Q：PDF 匯出後中文顯示為問號「?」？**
A：代表找不到系統中文字型。請確認 Windows 已安裝「微軟正黑體」（一般 Windows 10/11 預設已安裝）。

**Q：按傳送沒有反應？**
A：請確認網路連線正常，且 Groq API 服務可使用。

**Q：想更換 AI 模型？**
A：修改 `triage_bot.py` 開頭的 `MODEL` 常數，其他可用模型見 Groq 文件。換模型後建議重跑 `python evaluation/evaluate.py --models <模型名稱>`，確認分診表現。
